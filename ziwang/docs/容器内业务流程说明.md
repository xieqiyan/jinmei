# 容器内业务流程说明

本文档只说明当前版本容器内部的业务流程，不展开宿主机拓扑、外部交换机和网络命名空间的搭建过程。

## 1. 容器启动初始化

容器启动后先执行 `entrypoint.sh`，它只负责基础环境初始化：

```text
启动 ovsdb-server
启动 ovs-vswitchd
创建 /tmp/radio_test
创建并拉起 br0
给 br0 添加一条默认 NORMAL 流表
执行容器启动命令
```

`entrypoint.sh` 不自动完成参数加注、参数查询、组网守护、拓扑上报。业务程序需要由启动命令或人工手动启动。

## 2. 参数服务

参数服务启动命令：

```bash
python3 /usr/local/bin/radio_param_service.py
```

每个协议镜像只处理自己的协议：

```text
CKL 镜像：只处理 CKL
XTL 镜像：只处理 XTL
ZZW 镜像：只处理 ZZW
```

参数服务监听：

```text
UDP 10001
```

启动时参数加载顺序：

```text
1. 优先读取 /tmp/radio_test/<协议>_params.json
2. 如果状态文件不存在，则读取本协议配置文件
3. 如果配置文件也不存在，则使用默认值
```

配置文件路径：

```text
CKL: /tmp/radio_test/ckl_config.cfg
XTL: /tmp/radio_test/xtl_config.cfg
ZZW: /tmp/radio_test/zzw_config.cfg
```

## 3. 参数查询流程

外部向容器 `10001/UDP` 发送查询请求。

容器收到后检查：

```text
msgType == 0x0a
superOpt == 0x01
optEquip 匹配当前协议
```

查询响应返回到请求方 `10009/UDP`。

当前响应格式为：

```text
310B 响应头 + 当前设备协议参数
```

不再返回三套协议组合结构。

响应长度：

```text
CKL: 310 + 440  = 750B
XTL: 310 + 5863 = 6173B
ZZW: 310 + 5372 = 5682B
```

返回值规则：

```text
如果之前成功加注过，返回加注后的值
如果没有成功加注过，返回默认值
```

## 4. 参数加注流程

加注请求发送到容器：

```text
UDP 10001
```

当前加注使用短加注报文，不再使用完整 `CKL_PARAM / XTL_PARAM / ZZW_PARAM` 作为加注报文。

短加注长度：

```text
CKL: 9B
XTL: 12B
ZZW: 12B
```

字段顺序：

```text
CKL:
fmtVersion, radioType, nodeNo, radioFreq, radioPower, workFreqMode, radioRate, hostPrime

XTL:
fmtVersion, radioType, nodeNum, radioPower, freqType, freq, userRate, currentChannelNo, hostPrime

ZZW:
fmtVersion, radioType, nodeNum, radioPower, freqType, freq, userRate, superiorNetNo, hostPrime
```

固定字段：

```text
fmtVersion = 0x01
CKL radioType = 0x01
XTL radioType = 0x02
ZZW radioType = 0x03
```

XTL 和 ZZW 的 `hostPrime` 位于字段区最后 1 字节。

容器处理加注的流程：

```text
1. 判断报文是否为当前协议短加注报文
2. 按固定长度拆分短加注记录
3. 解析字段
4. 写入内存中的完整协议参数结构
5. 使用加注报文源 IP 作为 businessIp
6. 保存完整状态文件
7. 写入组网配置文件
8. 按字段逐个返回加注回执
```

回执目的端口：

```text
UDP 8882
```

回执格式：

```text
[0x13, result]
```

结果码：

```text
result = 0    成功
result != 0   失败
```

当前回执数量按字段数计算：

```text
CKL 一条 9B 短报文：6 个业务字段，返回 6 个 ACK
XTL 一条 12B 短报文：7 个业务字段，返回 7 个 ACK
ZZW 一条 12B 短报文：7 个业务字段，返回 7 个 ACK
```

示例：CKL 一次加注成功时，客户端应看到：

```text
ack 1/6 data=1300 result=success
...
ack 6/6 data=1300 result=success
```

## 5. 加注后的文件变化

加注成功后会更新状态文件。

状态文件路径：

```text
CKL: /tmp/radio_test/ckl_params.json
XTL: /tmp/radio_test/xtl_params.json
ZZW: /tmp/radio_test/zzw_params.json
```

状态文件保存：

```text
完整协议参数结构
解析后的字段摘要
本次短加注原始报文
```

加注成功后也会更新组网配置文件。

配置文件路径：

```text
CKL: /tmp/radio_test/ckl_config.cfg
XTL: /tmp/radio_test/xtl_config.cfg
ZZW: /tmp/radio_test/zzw_config.cfg
```

配置文件保存组网判断需要的字段，例如频率、速率、功率、主属台、业务 IP 等。

## 6. 组网守护进程

组网程序：

```bash
ckl_daemon
xtl_daemon
zzw_daemon
```

默认参数：

```text
监听接口: br0
控制网桥: br0
软件侧端口: eth-ns
上联端口: eth-up
```

等价启动形式：

```bash
ckl_daemon -i br0 -b br0 -n eth-ns -u eth-up
xtl_daemon -i br0 -b br0 -n eth-ns -u eth-up
zzw_daemon -i br0 -b br0 -n eth-ns -u eth-up
```

daemon 启动后执行：

```text
1. 读取本协议配置文件
2. 周期广播本机组网参数
3. 接收其他容器广播的组网参数
4. 维护邻居表
5. 判断哪些节点属于同一个有效子网
6. 动态更新业务通信规则
7. 写出 /tmp/radio_test/peers.json
8. 监听配置文件变化，支持加注后的热更新
```

有效子网判断规则：

```text
参数匹配
并且匹配集合中 hostPrime == 1 的节点数量恰好为 1
```

各协议参与匹配的字段：

```text
CKL:
radioFreq, radioPower, workFreqMode, radioRate

XTL:
radioPower, freqType, freq, userRate, currentChannelNo

ZZW:
radioPower, freqType, freq, userRate, superiorNetNo
```

`businessIp` 不参与参数匹配，只用于业务白名单和拓扑上报。

## 7. 邻居状态文件

组网 daemon 会生成：

```text
/tmp/radio_test/peers.json
```

该文件记录：

```text
本机参数
发现到的对端节点
对端 businessIp
参数是否匹配
是否可达
hostPrime 状态
```

`peers.json` 用于查看当前组网状态，也会被拓扑上报程序读取。

## 8. 拓扑上报流程

拓扑上报程序：

```bash
python3 /usr/local/lib/radio_protocol/topology_reporter.py
```

它周期读取：

```text
配置文件
peers.json
```

然后构造设备拓扑上报报文，发送到：

```text
UDP 8882
```

默认上报周期：

```text
2 秒
```

routeNum：

```text
CKL: 3
ZZW: 2
XTL: 4
```

拓扑上报内容来自 `peers.json`：

```text
本机 businessIp
对端 businessIp
对端是否 reachable
链路数量
```

当前没有真实硬件提供 `snr` 和 `fieldIntensity`，程序会生成合理范围内的模拟值。

## 9. 推荐容器内启动顺序

推荐顺序：

```text
1. 容器启动，entrypoint.sh 初始化 br0 和 /tmp/radio_test
2. 启动 radio_param_service.py
3. 执行参数加注
4. 执行参数查询，确认加注值已经生效
5. 启动 ckl_daemon / xtl_daemon / zzw_daemon
6. 启动 topology_reporter.py
```

这样可以保证：

```text
参数服务先启动，能够接收加注
加注成功后生成配置文件
daemon 启动时能直接读取有效配置
daemon 后续可以热加载配置变化
topology_reporter 启动后可以读取 peers.json 进行上报
```
