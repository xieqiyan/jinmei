# 启动参数说明

本文档只描述纯手动启动方式，不依赖 `scripts/setup_topology.sh`。下面按不同协议镜像分别说明容器内程序如何启动、默认参数是什么、哪些参数可以手动覆盖。

前提：

- 容器已经启动。
- 容器内 OVS 已由 `entrypoint.sh` 启动。
- 容器启动时，`entrypoint.sh` 会自动创建并拉起 `br0`。
- 容器启动时，`entrypoint.sh` 会自动创建 `/tmp/radio_test`。
- `eth-ns`、`eth-up` 等接口仍需要你手动创建、移入容器并加入 `br0`。
- 每个容器只运行一个协议，不存在 CKL/XTL/ZZW 混跑。

推荐业务顺序：

```text
1. 启动参数查询/加注服务
2. 从 namespace 侧执行参数加注
3. 从 namespace 侧执行参数查询确认
4. 启动组网 daemon
5. 启动拓扑上报程序
```

这样可以保证组网 daemon 启动前，协议配置文件已经由加注流程生成。

日志说明：

- 直接启动时，日志默认输出到当前终端。
- 如果希望后台运行并写入文件，可以手动使用 `nohup ... > 日志文件 2>&1 &`。
- 程序内部不强制写固定日志文件，这样手动调试时可以直接看到输出。

协议类型说明：

- 每个镜像只安装并启动自己的协议业务。
- `/usr/local/bin/radio_param_service.py` 是协议专用 wrapper，内部已固定协议类型。
- CKL wrapper 固定补齐 `--device ckl`。
- XTL wrapper 固定补齐 `--device xtl`。
- ZZW wrapper 固定补齐 `--device zzw`。
- 因此手动启动参数服务时不需要传 `--device`。

## CKL 镜像

镜像：

```text
jm-ckl:v1
```

镜像内协议入口：

```text
/usr/local/bin/radio_param_service.py 固定处理 CKL
```

### 1. 参数查询/加注服务

启动命令：

```bash
python3 /usr/local/bin/radio_param_service.py
```

默认参数：

```text
协议类型：ckl
监听地址：0.0.0.0
监听端口：10001/UDP
配置文件：/tmp/radio_test/ckl_config.cfg
状态文件：/tmp/radio_test/ckl_params.json
CKL 兜底配置：/tmp/radio_test/ckl_config.cfg
默认 IP：优先读配置文件，其次读 br0 IPv4，最后 0.0.0.0
```

可选覆盖参数：

```bash
python3 /usr/local/bin/radio_param_service.py \
  --bind 0.0.0.0 \
  --config-file /tmp/radio_test/ckl_config.cfg \
  --state /tmp/radio_test/ckl_params.json \
  --default-ip 10.0.0.1
```

通常不需要传这些参数。

### 2. 组网 daemon

启动命令：

```bash
ckl_daemon
```

默认参数：

```text
AF_PACKET 接口：br0
OVS bridge：br0
配置文件：/tmp/radio_test/ckl_config.cfg
邻居状态文件：/tmp/radio_test/peers.json
组网广播周期：1s
配置检查周期：0.5s
邻居老化时间：3s
```

可选覆盖参数：

```bash
ckl_daemon -i br0 -b br0
```

注意：CKL 当前配置文件路径固定为 `/tmp/radio_test/ckl_config.cfg`，不支持 `--config-file` 覆盖。

### 3. 拓扑上报程序

启动命令：

```bash
python3 /usr/local/lib/radio_protocol/topology_reporter.py
```

默认参数：

```text
邻居文件：/tmp/radio_test/peers.json
配置文件：/tmp/radio_test/ckl_config.cfg
目标 IP：从 businessIp 自动读取
目标端口：8882/UDP
上报周期：2s
routeNum：2
```

可选覆盖参数：

```bash
python3 /usr/local/lib/radio_protocol/topology_reporter.py \
  --peer-file /tmp/radio_test/peers.json \
  --config-file /tmp/radio_test/ckl_config.cfg \
  --dest-ip 10.0.0.1 \
  --dest-port 8882 \
  --interval 2
```

如果不传 `--dest-ip`，程序会从配置文件或 `peers.json` 的本地 `businessIp` 读取目标 IP。

## 手动启动注意事项

### 配置文件

组网 daemon 启动时必须能读取对应配置文件：

```text
CKL：/tmp/radio_test/ckl_config.cfg
XTL：/tmp/radio_test/xtl_config.cfg
ZZW：/tmp/radio_test/zzw_config.cfg
```

如果你按推荐顺序先启动参数服务、再执行加注，那么配置文件会由加注流程生成。

如果你跳过加注直接启动 daemon，需要手动准备配置文件。

### 目录

`/tmp/radio_test` 已由容器 `entrypoint.sh` 自动创建。参数服务保存状态文件和配置文件时也会自动创建父目录。

### 拓扑上报目标 IP

拓扑上报默认不需要传 `--dest-ip`，但配置文件里必须有：

```text
businessIp=10.0.0.x
```

否则上报程序会暂时跳过发送，并在日志中提示无法确定目标 IP。
